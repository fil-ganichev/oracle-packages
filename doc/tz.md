# Инструкция для ИИ: Создание готового Java-проекта "Oracle Packages в Java"

## 🎯 Цель
Создать полностью рабочий, компилируемый и покрытый unit-тестами Maven-проект на Java 19, который эмулирует функционал трех встроенных пакетов Oracle: `standard`, `utl_raw` и `utl_encode`.

## 💻 Стек и окружение
* **Язык:** Java 19.
* **Сборка:** Maven.
* **Тестирование:** JUnit 5, AssertJ (для удобных и читаемых утверждений), Mockito (для изоляции тестов и создания моков).
* **Логирование:** Logback + SLF4J.
* **Путь к JDK:** `C:\Program Files\jdk-19`.

## 📁 Структура проекта
Создай структуру проекта строго в директории `oracle-packages`:
```text
oracle-packages/
├── pom.xml
├── sql/                        # Здесь уже лежат исходные .sql спецификации
└── src/
    ├── main/
    │   └── java/
    │       └── oracle/
    │           └── packages/   # Базовый Java-пакет
    └── test/
        └── java/
            └── oracle/
                └── packages/   # Unit-тесты с AssertJ и Mockito
```

## 🛠 Архитектурные требования (Реализуй на свое усмотрение)

### 1. Кастомная система типов (Wrapper-классы)
Создай иерархию классов для имитации типов данных Oracle:
* Базовый тип: `Var` (интерфейс или абстрактный класс).
* Наследники: `Varchar2Var`, `NumberVar`, `RawVar`, `BlobVar` и другие, которые встретятся в спецификациях.
* Каждый класс должен иметь методы:
  * `isNull()` — возвращает true, если значение отсутствует.
  * `get()` — возвращает сырое Java-значение.
  * `set(...)` — мутирует или обновляет значение.

### 2. Правила именования и сигнатур методов
* **Default-параметры:** Если в SQL-спецификации параметр имеет значение по умолчанию (`DEFAULT` или `:=`), в Java-методе оберни этот параметр в `Optional<T>`, где T — соответствующий тип `Var`.
* **Перегрузка методов:** Стандартная перегрузка Java запрещена. Если методы в SQL имеют одинаковое имя, именуй их в Java строго по шаблону:
  * `someMethod` (первая/главная версия)
  * `someMethod$1` (вторая версия)
  * `someMethod$2` (третья версия)

### 3. Логика, Заглушки и Комментарии
* **Документация:** Найди в интернете официальную документацию Oracle для `standard`, `utl_raw` и `utl_encode`, чтобы в точности воссоздать логику функций (например, побитовые операции в `utl_raw` или кодирование в `utl_encode`).
* **Заглушки:** Если метод одного пакета ссылается на другой пакет, сделай внутри метода-вызывающего временную заглушку (stub), либо используй механизмы Mockito в тестах для изоляции этих вызовов. Project должен успешно собираться.
* **Язык:** Все комментарии к классам, методам и логике внутри кода пиши **на кириллице**.

## 🧪 Требования к тестированию и сборке
1. Проект должен успешно проходить команду `mvn clean test` (или `mvnw.cmd clean test`). Настрой `pom.xml` под Java 19, подключи JUnit 5 платформу, AssertJ, Mockito и Logback.
2. Напиши качественные Unit-тесты на JUnit 5 для каждого реализованного метода в пакетах `standard`, `utl_raw` и `utl_encode`.
3. В тестах активно используй fluent-стиль **AssertJ** для проверок (например, `assertThat(...).isEqualTo(...)`).
4. Тесты должны покрывать как успешные сценарии, так и граничные случаи (например, передачу пустых `Var` объектов или `Optional.empty()`).

## 🚀 Начни работу по шагам:
1. Напиши корректный `pom.xml` с учетом всех зависимостей.
2. Проанализируй SQL-файлы в папке `sql/`.
3. Реализуй архитектуру wrapper-классов `Var`.
4. Напиши код пакетов и тесты к ним, планомерно двигаясь по файлам спецификаций.
